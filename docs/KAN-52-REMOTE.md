# KAN-52 — TV Player remote adapter

The Tauri control WebSocket now forwards JSON events/results to React using `tv-player-ws-message`, and exposes the **whitelisted** `ws_media_command` invocation (no arbitrary socket sends). After identification the connection subscribes to `media.room.changed` and `media.room.closed`, then requests `media.rooms.snapshot`. UI also requests a snapshot after installing its event listener.

`MediaControlBridge` is mounted only while TV Player is connected. It recognizes remote media keys `MediaPlayPause`, `MediaPlay`, `MediaPause`, `AudioVolumeUp`, `AudioVolumeDown`, and `AudioVolumeMute` — only if the current playback has a real `video[data-homecloud-media]` element and a valid Backend room/attach epoch. It first applies the local operation and then notifies Backend using `media.room.control`, preventing echo. UI-initiated `media.room.control` events are acknowledged `APPLIED` only if the element exists and the operation succeeds. Otherwise they return `FAILED: PLAYER_NOT_READY`. It sends TV `media.room.heartbeat` every 20s while a room exists and independent `media.room.report` updates from actual media-element playback/pause events.

This does NOT add a media decoder. There is currently no `video[data-homecloud-media]` in the waiting screen, so on-device Play/Pause execution and Android hardware volume/Mute have not been established. Future HCM1 decoding must mount a real video element or extend the bridge for a native Media3 adapter, then run a physical TV acceptance test. Don't report full completion of MG-12 on CI alone.
